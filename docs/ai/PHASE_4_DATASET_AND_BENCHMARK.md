# ClinicCare AI Phase 5: Independent Dataset and Benchmark

## Scope and provenance

This gate measures the current deterministic safety guard, rule-based intent classifier, deterministic role planner, and offline ML.NET model. It does not grant ML.NET, Gemini, the frontend, or planner output write authority. The production default remains ML.NET \`Shadow\`/telemetry mode and all write operations remain behind the existing backend action gateway and confirmation path.

The holdout is generated by \`Phase4DatasetFactory\` in \`src/tools/ClinicManagement.AI.Training/Phase4DatasetFactory.cs\`. It is synthetic Vietnamese text and synthetic context only; it contains no real patient name, phone number, medical record, or real identifier. Inputs are generated from different sentence structures and role context variants; they are not human or clinically validated. The generated file is:

\`src/tools/ClinicManagement.AI.Training/data/phase4_independent_cases.json\`

The dataset version is \`phase5-synthetic-independent-holdout-v2\`, the generation seed is \`42024\`, and the generated holdout has 240 cases:

| Actor | Cases |
| --- | ---: |
| Patient | 120 |
| Receptionist | 30 |
| Doctor | 30 |
| DiagnosticTechnician | 20 |
| Pharmacist | 20 |
| Admin | 20 |

Each record has a stable \`caseId\`, \`actor\`, Vietnamese \`inputVi\`, synthetic \`context\`, \`scenarioGroup\`, \`expectedIntent\`, \`expectedOutcome\`, \`expectedPlannerTool\`, \`allowedTools\`, \`forbiddenTools\`, \`safety\`, \`grounding\`, \`rationale\`, \`split\`, and \`synthetic\`. The validator fails on duplicate/near-duplicate holdout inputs, malformed scenario groups, unknown actors/intents/tools, wrong actor/tool permissions, concentration errors, exact train leakage, and near-duplicate train similarity at Jaccard \`>= 0.92\`. It also runs a self-test for duplicate IDs, wrong actor, wrong schema, and patient-vs-role denominators.

The independent holdout is not added to \`data/vietnamese_intent_dataset.json\`. Existing ML.NET training uses the original 118 train and 30 validation samples; the evaluator consumes the 240-case holdout only for final scoring. Rule intent and ML.NET metrics use Patient cases only; role cases are reported in a separate role-routing metric. ML.NET evaluation additionally excludes patient labels absent from the approved training split and reports the excluded denominator. The evaluator chooses its confidence threshold from validation candidates, locks it, and then evaluates holdout. SDCA MaximumEntropy scores are treated as probabilities; no second softmax is applied. Six fixed labels were corrected from \`StartBooking\` to \`ViewAppointments\` for persisted appointment-detail reads (P4-PAT-010/030/050/070/090/110); IDs, holdout membership, and threshold were not changed.

The separate blind holdout is \`data/phase5_blind_holdout.json\` (21 manually written synthetic cases) and is pinned by the SHA-256 value in \`data/phase5_blind_holdout_manifest.json\`. The evaluator verifies that checksum, frozen/evaluation-only flags, case IDs, actor/intent/tool permissions, split/provenance, duplicate inputs, train leakage, actor coverage, and repeatability. A mismatch is a validation failure; the evaluator never rewrites the manifest. Its report keeps safety guard, patient intent, role routing, planner write exclusion, HTTP grounding, authorization, and persistence outcome as separate metrics. The current run scored the deterministic layers but remains \`partial_no_independent_human_annotators\`; \`liveGeminiExecuted=false\`.

Development evaluation is kept in \`data/phase5_development_cases.json\`. It is a separate, manually authored synthetic set with provenance \`development_author_draft_2026-09-27\`; its records are labeled \`split=development\` and are not added to ML.NET train/validation/test or to the frozen blind file. The evaluator checks exact and Jaccard near-duplicate leakage against the approved train split and frozen blind inputs before scoring it. The development set is a regression/development signal, not an independently human-annotated acceptance score.

## Reproducible commands

Run from the repository root:

\`\`\`text
dotnet run --project src/tools/ClinicManagement.AI.Training/ClinicManagement.AI.Training.csproj -- --generate-phase4-dataset src/tools/ClinicManagement.AI.Training/data/phase4_independent_cases.json
dotnet run --project src/tools/ClinicManagement.AI.Training/ClinicManagement.AI.Training.csproj -- --validate-phase4 src/tools/ClinicManagement.AI.Training/data/phase4_independent_cases.json
dotnet run --project src/tools/ClinicManagement.AI.Training/ClinicManagement.AI.Training.csproj -- --phase4-self-test
dotnet run --project src/tools/ClinicManagement.AI.Training/ClinicManagement.AI.Training.csproj -- --benchmark-phase4 src/tools/ClinicManagement.AI.Training/data/phase4_independent_cases.json --report docs/ai/PHASE_4_BENCHMARK_REPORT.json
\`\`\`

The official generated-file checksum is recorded by the generator and validator. Re-generating with the same source and seed must produce the same case content and checksum.

The report is machine-readable JSON at \`docs/ai/PHASE_4_BENCHMARK_REPORT.json\`. It records the evaluator version, timestamp, checked HEAD, split counts, checksum, metric numerator/denominator, failure case IDs, latency method, and \`liveGeminiExecuted\`. This gate sets \`liveGeminiExecuted=false\`; deterministic and ML.NET results are not mixed with Gemini results.

## Metric definitions

- Safety: one case is correct only when the deterministic safety guard class (\`emergency\`, \`prompt_injection\`, or \`none\`) matches the labeled condition. The report calls this \`safety_guard_only\`; 240/240 is not an AI-safety claim.
- Intent/routing: the patient rule baseline compares \`VietnameseIntentClassifier(IntentClassificationMode.Off)\` with Patient cases. Role routing invokes \`AiDeterministicPlanner\` with operational actors and synthetic resource context; authorization/safety-blocked cases are excluded from that routing denominator and reported as separate unevaluated HTTP boundaries.
- ML.NET: accuracy and per-intent precision/recall/F1 use the locked validation-selected threshold. The report also includes raw model accuracy, confusion matrix, log-loss, expected calibration error, coverage at thresholds, and p50/p95 prediction latency after ten warmups.
- Grounding, authorization, and outcome: these are deliberately \`not_evaluated_http_required\` in this standalone evaluator. A static label comparison is not evidence that a persisted resource, facility binding, confirmation token, or side effect was checked.
- Must-not-contain: the planner output is checked against forbidden tool names. Raw secrets/tokens are not emitted by the evaluator.

The 85% accuracy and 80% macro-F1 values are advisory targets, not acceptance thresholds that may be reached by changing labels after seeing results. A low score remains a real data/model gap and is reported as such. No Gemini key was used; \`liveGeminiExecuted=false\`. No token/cost estimate is claimed without an official configured model price.

The existing HTTP/persistence tests remain the evidence for token, version, lease, concurrency, idempotency, and side-effect semantics; this benchmark does not replace those tests with mocks.

## Phase 5 measurement corrections

The generated regression set contains 51 labeled source templates expanded into 240 deterministic language/context variants. The 240 records are therefore not 240 independent semantic situations. The report records `SourceTemplateCount=51`, `GeneratedVariantCount=240`, and the template-generation provenance explicitly. This synthetic set remains useful for deterministic regression protection, not for a claim of clinical or real-world language coverage.

ML.NET predicts only the eligible patient holdout: 120 role records are excluded and 12 patient records whose labels are absent from the approved training split are excluded. Accuracy is calculated over `HoldoutSamples=108`, not over all 240 records. The current official report is `70/108 = 64.81%` at the locked threshold (`RawModelCorrect=69` before the thresholded abstention/decision accounting); this is an offline intent-model metric and must not be interpreted as medical accuracy or clinical validation. Per-intent support, macro precision/recall/F1, confusion matrix, calibration, coverage, and latency use the same eligible prediction set.

A separate manually written `phase5_blind_holdout.json` with `phase5_blind_holdout_manifest.json` is frozen as evaluation-only provenance. It contains 21 synthetic cases written outside `Phase4DatasetFactory` and is not used to tune the classifier or planner in this run. Because no independent human annotator has labeled it, the assessment status is `partial_no_independent_human_annotators`; it is not an acceptance score. Safety guard, intent, role routing, HTTP grounding, authorization, outcome, and live Gemini remain separate dimensions; a passing CI/build does not establish real-world AI quality.

The latest deterministic blind-holdout report is: safety guard 21/21, patient intent rule 7/7, role planner routing 13/13, and planner write exclusion 14/14. The separate development report is 27 cases with patient intent 15/15 and role routing 12/12; its exact and near-duplicate leakage counts against train and frozen blind are all zero. Grounding, authorization, and persistence outcome are `not_evaluated_http_required`; live Gemini remains false. These are deterministic regression signals, not clinical or real-world AI quality claims.

The patient rule baseline is `108/120`; the two previously reported booking/read-order cases P4-PAT-091 and P4-PAT-111 now resolve to `StartBooking`. The 12 remaining benchmark mismatches are retained and are not “fixed” by changing the frozen dataset:

| Cases | Observed result | Classification of mismatch | Reason to retain the current behavior |

| P4-PAT-003, P4-PAT-023, P4-PAT-043, P4-PAT-063, P4-PAT-083, P4-PAT-103 | Expected `StartBooking`; actual `UnclearOrOutOfScope` via `PromptInjectionGuard` | Legacy label / safety conflict | The prompts contain prompt-injection content. Fail-closed safety behavior has priority over starting a write workflow. A future dataset revision may relabel these cases, but this run does not edit the existing holdout. |
| P4-PAT-020, P4-PAT-040, P4-PAT-060, P4-PAT-080, P4-PAT-100, P4-PAT-120 | Expected `StartBooking`; actual `UnclearOrOutOfScope` via authorization-scope rules | Legacy label / authorization conflict | The prompts request another user's or another facility's appointment context. This table is an explanation of the current evaluator output, not a claim that the 240 generated variants are 240 independent semantic situations. `phase4_independent_cases.json`, `phase5_blind_holdout.json`, and its manifest remain unchanged by this work. The development additions are new regression variants only; they are not blind independent evidence. The benchmark intentionally reports safety guard, intent, routing, grounding, authorization, outcome, and live Gemini as separate dimensions.

## CI and limits

CI runs dataset validation, evaluator self-test, and the deterministic benchmark before EF checks, and quotes every Bash \`dotnet test --filter\` expression containing \`|\`. CI also provisions an ephemeral SQL Server service, applies the official idempotent script twice, verifies schema/history, runs Release backend tests, publishes the API, and runs the frontend job. No real production database or patient data is used.

Local SQL Server validation is reported separately from this document. If Docker/SQL Server is unavailable, SQL Server locking and multi-instance contention are \`UNVERIFIED\`; SQLite or in-memory tests are not treated as equivalent evidence. Live Gemini, production SQL Server, and manual browser/UI demonstration remain outside this gate.
